# Evidence and claim policy

仓库中的能力、验证和性能结论必须能追溯到具体 commit、环境与产物。以下标签用于 README、PR、Issue、验证报告和发布说明。

## REAL

`REAL` 表示声明所指的真实外部组件或完整链路已实际运行，并保存了足以复现的证据。记录至少包含：

- commit SHA、日期、操作系统和关键工具版本；
- 明确命令、输入、服务拓扑与前置条件；
- 退出码、测试摘要或脱敏产物位置；
- 已知限制、清理结果和未覆盖范围。

例如，真实 Docker、PostgreSQL、Redis、Kind 或 vLLM 运行只有在对应组件确实启动并完成断言后才能标记 `REAL`。

## SIMULATED

`SIMULATED` 表示结果来自 mock、fake runtime、离散事件仿真、故障注入替身或合成数据。必须说明被替代的真实组件、仿真假设和不能外推的结论。仿真通过不能改写成真实集群、真实 GPU 或生产流量已通过。

## NOT RUN

`NOT RUN` 表示验证未执行、没有完成或环境前置条件缺失。应记录原因和建议命令；代码存在、测试被收集、静态审查通过或其他分支的旧结果都不能替代本次运行。

## Wording rules

- 区分“已实现”“自动化测试通过”“真实环境运行通过”和“生产可用”。
- 性能数字必须给出 workload、样本量、硬件/运行时、统计口径和原始产物。
- 修复行为问题后，旧 benchmark 和旧演示结果自动失效，必须基于修复后的冻结 commit 重跑。
- 不使用 `production-ready`、`production-grade`、`HA` 或“支持真实 GPU/Kubernetes”等表述，除非证据覆盖了该声明的完整边界。
- 无法核验时选择更窄的事实陈述，并使用 `NOT RUN`，不要推测为通过。
